# 常见问题

适用于本地 MCP 版 0.6.0-alpha.2。首次安装请按 [快速上手](QUICKSTART.md) 操作。

## 必须有 ChatGPT Sites 才能用吗？

本地版不需要 Sites，需要自己的电脑、Node.js、支持本地 stdio 的 MCP 客户端，以及用于账户查询的 OpenRouter Management Key。Sites 网页版才需要相应云端权限。本地版不是 ChatGPT 云端连接器。

## 为什么安装后没有网页？

npm 安装的是本地 MCP 服务，在客户端对话中调用工具。README 截图展示 Sites 网页版；安装 npm 包不会创建同款网页或云端站点。

## 为什么找不到 doctor，或者版本不对？

自检从 0.6.0-alpha.2 开始提供。检查实际安装目录的 `node_modules/@cyuanxv/openrouter-analytics-mcp/package.json`，并确认客户端指向同一份安装。明确安装 `@0.6.0-alpha.2`；当前 npm 的默认 latest 仍是旧版。不要根据状态工具的共享核心 `version=0.5.0` 判断包版本，应看 `adapter_version`。

## Node 已经装了，为什么还启动失败？

本地版支持 Node 22.22+（22 系列）或 24+，不支持 Node 23。终端和客户端可能使用不同 Node，需检查客户端 `command` 的绝对路径。SQLite 实验性提示本身不代表失败；以服务能否连接、工具结果和错误信息为准。

## Key 已经配到客户端，为什么终端自检还说未配置？

终端不会自动继承客户端秘密设置。向自检进程安全提供 `OPENROUTER_MANAGEMENT_KEY` 和 `OPENROUTER_WORKBENCH_DATA_DIR`，再运行命令。反过来，终端自检成功也不代表客户端已经拿到同一份配置。不要把 Key 贴进聊天来排查。

## 普通 OpenRouter API Key 可以吗？

本教程使用 Management Key。自检会确认其管理权限，普通模型调用 Key 无法通过这一项。不要加 `Bearer ` 前缀或带入空格、换行。工作台不会替你创建、修改或撤销 Key。

## 自检通过，是不是全部功能都正常了？

不是。自检确认 Node、基础账户读取和目录访问条件，不测试全部分析接口，不打开数据库验证完整性，也不确认磁盘空间或迁移成功。还要在客户端依次测试状态、余额、费用分析和报告读回。

## 状态里 authentication_verified、connectivity_verified 是 false，要修吗？

本地版没有 Sites 云端身份，前者为 false 是正常的；状态工具本身不做上游请求，因此后者为 false 不能用来判定 Key 无效。用自检确认基础权限，再实际调用账户工具。

## 余额能查到，为什么费用或报告有“未知”？

余额读取和分析数据是两层能力。权限、上游接口、时间范围、历史长度或返回结果完整性可能限制分析。报告需要当前、对比期及异常基线数据。先看对应错误和完整性说明；不要把未知当零，也不要为了测试而制造付费调用。网络超时、限流或服务异常可稍后重试基础查询。

## 提示数据目录不存在、不是绝对路径或权限不对怎么办？

选择当前用户可访问的专用私有目录，填写完整绝对路径。不要用根目录、家目录本身、源码或安装目录，不要使用符号链接目录或链接数据库。目录尚未创建时自检不会帮你创建，先正常启动服务，再自检。权限问题按 [自检说明](DOCTOR.md) 处理，不要用管理员权限绕过。Windows 需自行确认私有 ACL。

## 为什么周报和我按周一至周日统计的不同？

不填 `end_date` 时，周报统计所选时区最近 7 个完整日，截止今天零点，不含今天。不是固定的上一自然周。需要上一自然周时，将 `end_date` 设为本周一的日期，结束日不含；历史报告的异常证据可能无法提供，不能据此断言历史没有异常。

## 为什么重复生成的报告没有更新？

相同种类、时区和结束日会复用已存报告，避免重复生成。已有报告是生成当时的观察记录，不是实时账单。先核对日期和生成时间；本教程不删除或覆盖旧报告。

## 会自动发 Telegram、每周定时运行吗？

本地版没有内置调度或自动发送。生成报告只保存记录，`should_notify=true` 不等于已经发出；不能把模拟或人工编写的消息 ID 当真实回执。Sites 版也需额外配置自己的云端任务与通知通道。电脑或客户端关闭后，本地进程不能继续运行。

## 会扣模型调用费，或者改变线上模型吗？

本教程的工具不执行付费推理、充值、Key 修改或生产路由切换。查询账户会向 OpenRouter 发送请求；报告生成会查询数据并写本地数据库。MCP 客户端自身的对话费用和数据政策由该客户端决定。

## 重启或升级后，报告会丢吗？

使用同一个数据目录，已保存记录会保留。卸载 npm 包不会自动删除数据库。升级前停止所有相关实例，备份整个专用数据目录；不要公开上传数据库。换到新目录后看到空列表，不代表旧数据已删除。

## 怎样提交问题才不会泄露隐私？

到 [GitHub Issues](https://github.com/cyuanxv/openrouter-analytics-mcp/issues) 提供操作系统、包版本、Node 版本、失败步骤和脱敏错误代码。`doctor --json` 不输出 Key、余额或账户标识，但分享前仍应检查附加的终端内容。不要上传 Key、含密钥配置、账户标识、私人报告或整个数据目录。
