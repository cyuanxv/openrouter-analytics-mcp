# 怎样看费用报告

此文对应正在本地开发的报告摘要改进，尚未发布到 npm 或 MCP Registry。现有 0.6.0-alpha.2 安装包暂不包含这些改动。

新生成的周报与异常检查先回答三个问题：本期花了多少、比上期多花或少花多少、哪些模型的费用变化最大。随后列出“现在能确认”“还不能确认”和下一步建议。

例如模拟数据中，本期 $120、上期 $100；模型 A 两期都是 $80，模型 B 从 $20 增至 $40。报告会写“本期 $120，比上期多花 $20（20%），主要变化是模型 B 多花 $20”，而不会把费用最高但没有变化的 A 当作上涨来源。

- 日期范围沿用原规则，结束日不含；周报是 7 个完整日，币种为美元。
- 上期为零时只展示增加金额，不计算百分比；缺少任一期总费用时不比较。
- 只有两期模型明细均完整，并且分别与账户费用核对一致，才列出最多 3 个变化最大的模型（包括上涨与下降）。这只是账单贡献，不证明请求行为或价格变化的原因。
- 明细截断、为空、不可访问或核对不一致时，写明不能判断模型变化来源。没有返回的模型不会被直接当成零。
- 异常检查只评价数据足够的日期。有跳过日期时明确提醒，不能把部分日期“未发现候选”理解为整个报告期没有异常。归因不足时仍保留异常线索。
- 生成与读取报告的 MCP 文本先展示易读摘要，结构化结果保留原有费用、明细和证据，并新增 `summary` 与 `prior_models`。通知文本同步使用摘要并保留必要限制，超长详细归因请读取完整结构化报告。
- 已保存报告保持原样，不重算、不补写摘要；同一种类、时区和结束日再次生成仍返回原记录。需要看到新格式时，等待升级后的新一期报告即可。
- 生成报告不等于发送通知。通知认领、实际回执和发送策略没有改变。

两期模型对比新增一次有行数上限的上期模型查询；数据请求仍为账单查询，不执行模型推理。此改进在共享核心实现，本地 MCP 与未来自行部署的 Sites 新版本可复用；本次没有部署任何 Sites 服务。
