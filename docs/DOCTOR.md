# 安装与配置自检

从本地版 `0.6.0-alpha.2` 开始提供；旧版 `0.6.0-alpha.1` 不支持 `doctor`。Sites 云端版不使用此命令。

从完整源码构建本地包后，在 `packages/local-mcp` 中运行 `node dist/stdio.js doctor`；安装 npm 包或 tarball 后运行 `./node_modules/.bin/openrouter-analytics-mcp doctor`。正常 MCP 配置仍不加参数。

通过终端或 MCP 客户端的秘密环境设置提供 Key；不要把真实 Key 写进示例命令。终端与 MCP 客户端不共享配置，需在实际使用的环境分别检查。

| 检查结果 | 说明与处理办法 |
|---|---|
| Node 版本不支持 | 使用 Node.js 22.22+（22 系列）或 24+。23 不受支持；核对 MCP 客户端指定的 Node 路径。 |
| Key 未配置或格式不正确 | 在秘密环境设置中填写 Management Key；避免空格、换行、Bearer 前缀和示例占位文本。 |
| Key 有效但不是 Management Key | 使用自己的 Management Key；普通模型调用 Key 不够。自检不会创建、替换或撤销 Key。 |
| 身份被拒绝（401） | 检查当前环境中的 Key 配置与 OpenRouter Key 状态。不要将 Key 发给项目维护者。 |
| 读取权限被拒绝（403） | 检查 Management Key 和账户、组织访问限制。 |
| 超时、网络失败、限流或服务异常 | 结果为“待确认”，不意味着 Key 无效。检查网络后稍后重试，不关闭证书校验。 |
| 数据目录未配置或不是绝对路径 | 配置本工具专用目录；不能使用根目录、家目录、源码或安装目录。 |
| 目录尚未创建 | 检查通过的是父目录访问权限；首次正常启动将创建目录，再次自检前不会显示全通过。 |
| 目录或数据库无读写权限 | 检查当前用户权限、只读磁盘和路径；不要用管理员权限绕过问题。 |
| 目录或数据库是链接 | 选择新的专用目录，保留原数据库及备份，不删除或覆盖文件。 |
| 目录或数据库允许其他用户访问 | 停止实例并备份，确认专用目录后设置目录 0700、数据库 0600；自检不会代为修改。 |
| Windows ACL 未核实 | 在目录安全设置确认仅当前用户可访问；不能凭读写权限断言隐私通过。 |

默认仅访问官方 `GET /api/v1/key` 与 `GET /api/v1/credits`，以官方返回的 `is_management_key` 及合法的余额响应分别确认权限和连接。参考：[Key 信息](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key)、[账户余额](https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits)。Key 的有效性不能仅靠字符串格式判断。

加 `--offline` 时不发请求；加 `--json` 时输出稳定代码及中文解释。退出码：0 基础检查通过、1 发现错误、2 未完整验证；自动化调用方必须区分 0 和 2。Key、账户标识、余额和原始异常不写入输出。

自检不创建目录、不试写文件、不打开数据库，也不执行迁移。权限检查不保证实际写入、磁盘空间或数据库完整性。账户通过仅代表基础余额读取成功，不保证全部分析接口均可用。没有付费模型调用、充值、密钥修改、通知发送或生产路由切换。
